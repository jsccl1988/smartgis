Views 窗口体系 · 进程体系

终局产品壳 SmartGIS.exe 的 as-built 总览： 单 PE 按 --type= 分派进程角色；Browser 侧用 Chromium 风格 ui::views::Widget 托管 chrome，地图 HWND 挂在 MapViewport 上。不含 Legacy MFC / WinUI / CEF。

1. 总览

一个映像、四个角色。用户启动不带 --type 时进入 Browser（UI + chrome）。 同一 PE 可被 Browser 以 CreateProcess 再拉起为 GPU / Renderer 子进程。 Utility 角色在 Views host 里未链接（直接返回 1）。

Browser UI Renderer GPU（今日 OOP 主路径） Utility 预留
As-built 要点： GisContentsImpl::StartRenderProcess 当前用 named pipe 拉起 --type=gpu（注释标明 invitation 双启仍是 WIP）。 Renderer 入口 RendererMain 已接 invitation；Browser 内多数地图逻辑仍经 MapSession 进程内 present（Map2d / Scene3d）。

2. 进程体系

2.1 分派：content_main + ViewsContentHost

wWinMain 解析 CLI（CLI11）后填充 ContentMainParams， 交给模板函数 content::content_main。Host 必须满足 content_main_host concept（四个 *_main）。 

wWinMain (src/app/views/app/main.cc)
  │  parse_views_launch_options  →  ViewsLaunchOptions
  │  apply_shell_canvas_preference
  ▼
content::content_main(params, ViewsContentHost)
  │  process_type_set ? params.process_type
  │                  : ProcessTypeFromCommandLine(--type=)
  ├── kBrowser  → host.browser_main  → app::run_browser_main
  ├── kRenderer → host.renderer_main → content::RendererMain
  ├── kGpu      → host.gpu_main      → gpu::GpuMain
  └── kUtility  → host.utility_main  → return 1  (未链接)
角色开关入口函数主要循环
Browser 省略 / browser app::run_browser_main Widget::run_loop（GetMessage）
Renderer --type=renderer content::RendererMain IPC recv → Workspace / 工具
GPU --type=gpu gpu::GpuMain pipe + PeekMessage → draw / FrameReady
Utility --type=utility Views host stub 未实现（返回 1）

2.2 子进程启动（Browser → GPU）

content::GisContents 实现（GisContentsImpl）在 StartRenderProcess 里：

  1. 创建 Job Object（KILL_ON_JOB_CLOSE），Browser 退出则杀子进程。
  2. 建 named pipe server：--pipe= / --session= / --parent-pid=。
  3. CreateProcessW 同一 exe，命令行追加 --type=gpu。
  4. 子进程进 Job；等待 client connect；收 kHello，回 kHelloAck。
  5. 起 recv_thread_ 收 FrameReady / SharedHandle 等。

并行存在 launch_invited_child（OutgoingInvitation），供未来 renderer+gpu 双启；今日热路径仍是 pipe GPU。

2.3 Renderer / GPU 运行时

RendererMain

  • IncomingInvitation::accept → Channel "renderer"
  • 发 kHello（role=renderer）
  • 循环：父进程退出 / kShutdown 结束
  • kOpenView → ViewSlot + tool::Workspace
  • 指针 / 工具 / catalog / plugin 经 Workspace 分发
  • 禁止加载 D3D/GL（paint 只在 GPU）

GpuMain

  • 解析 argv；--self-test 走短路径
  • 否则 run_server：接 pipe 或 invitation
  • kHello（role=gpu）→ 等 kHelloAck
  • kOpenView / resize / draw 请求
  • draw_and_swap → SharedHandle + kFrameReady
  • 兼跑隐藏 HWND 的 Win32 消息泵

2.4 关闭子进程

GisContentsImpl::Shutdown()
  running_ = false
  pipe_.send_empty(kShutdown)           // GPU
  renderer_pipe_.send_empty(kShutdown)  // Renderer（若已启）
  close pipes → join recv threads
  WaitForSingleObject(process_, 3000)
  CloseHandle job_                      // KILL_ON_JOB_CLOSE 兜底

3. 窗口体系

Browser 不直接碰 HWND 布局细节。它通过 BrowserUiDelegate 抽象（实现类 BrowserView）驱动 chrome。 顶层原生窗口是 ui::views::Widget（一个 HWND + View 树 + 消息泵）。

  ├── MapSession          文档 / 相机 / Map2d / Scene3d / ToolSession×3 / gestures
  ├── PluginShell         插件贡献（Ambox 命令等）
  └── BrowserUiDelegate → BrowserView
        └── Widget  (HWND "SmartGIS Views", FrameKind::kCustom)
              └── FrameView  (自绘标题栏 / 最大化按钮)

                          │     │     │     │              ├── MapViewport(kMapData)
                          │     │     │     │              └── MapViewport(kScene3d)

3.3 地图 HWND 挂接

BrowserView::init_shell → attach_viewports()： 三个 MapViewport 分别对 Edit / Data / Scene3d 角色挂 child HWND， 再绑 ToolSession、手势、GisContents observer。 Shell 栅格通过 Widget::set_on_shell_published 提交到地图 overlay （chrome 与地图合成，不在 Widget 里混画 GPU 帧）。

4. 生命周期：启动 · 运行 · 关闭

4.1 启动（Browser）

  1. wWinMain：tracing、CLI、shell canvas 偏好、ContentMainParams。
  2. content_main → ViewsContentHost::browser_main → run_browser_main。
  3. DPI awareness；可选强制 ContentMapView（self-test / showcase）。
  4. Browser::init： session_.init_tool_sessions() → PluginShell → create_browser_ui → ui_->init_shell()。
  5. BrowserView::init_shell： Widget::init（CSD 1280×800 DIP）→ set_will_close → build_contents → 绑 Map2d/Scene3d → attach_viewports / gestures / catalog。
  6. 可选启动 debug console；加载 atmosphere fields。
  7. Browser::show → widget_.show + fit extent。
  8. 正常路径 browser->run_loop()；self-test / showcase 走旁路。

4.2 运行

Widget::run_loop()
  └── GetMessage / DispatchMessage
        ├── WM_PAINT / shell compositor  →  Skia/GDI shell raster
        ├── 鼠标键盘  →  View 树 hit-test / focus
        ├── MapViewport child HWND  →  手势 / Draft / present
        │     ├── 进程内 Map2dPresenter / Scene3dPresenter
        │     └── 可选 GisContents OOP GPU（SharedHandle present）
        └── WM_CLOSE  →  fire_will_close → DestroyWindow → PostQuitMessage

4.3 关闭（顺序敏感）

必须先拆地图 HWND / Vista，再 DestroyWindow，避免 userdata / present 悬空。

  1. 用户关窗 → WM_CLOSE → Widget::fire_will_close。
  2. 回调 Browser::prepare_close（幂等）： session_.prepare_close() → ui_->prepare_shell_close() → 三个 MapViewport::detach()。
  3. DestroyWindow；消息泵退出；run_browser_main 返回。
  4. ~Browser：再次 prepare_close → 清 observer → PluginShell::shutdown → ui_.reset() （析构 BrowserView / Widget）。
  5. 若曾 OOP：GisContents::Shutdown 发 kShutdown、关 Job。
WM_CLOSE
  → Widget::will_close_  →  Browser::prepare_close
       ├── MapSession::prepare_close
       └── BrowserView::prepare_shell_close
             └── MapViewport::detach × 3
  → DestroyWindow(hwnd)
  → run_loop 返回
  → ~Browser
       ├── prepare_close (no-op if done)
       ├── plugins_->shutdown()
       └── ui_.reset()  →  ~BrowserView → ~Widget
