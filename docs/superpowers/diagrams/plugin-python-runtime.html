glang 拥有 CPython，插件只登记

进程内一个解释器：app::py::Interpreter（glang.runtime/exec/session/cpython）。脚本 import glang.plugin。插件运行时不调用 Py_Initialize。内核仍是 C++。套件门禁仍是 required_marks + score_id。

分层（谁拥有什么）

脚本

  • import glang.plugin
  • 返回值是变量，终态去掉 as_
  • kind=python 的 start / stop 按目录
  • 插件 UI 留在 chrome 进程

glang · 解释器

  • app::py::Interpreter
  • 隔离 Py_InitializeFromConfig
  • eval / exec_source / exec_file
  • Debug 为桩（python_enabled 在 is_debug 时关闭）
  • 回调由 glang 持有，进内核前放 GIL

glang.plugin 登记表

  • C++：app::py::register_fn
  • 按名调用既有 eval_*
  • 不增长 Op（kCount == 105 直到删表）
  • 落到 CapabilityHost
  • 插件运行时只登记 / 注销

退役 · opcode 管线

  • 今天套件仍走 parse_python → check_suite → lower_program → eval_module
  • 阶段 3 起套件改走 main()，本车道不再执行套件
  • 转绿后删除 ANTLR / sema / lower / Op / LanguageExtension
  • 本车道不加入实时调用

停用一个包：先 unregister_fn，再丢掉 glang 持有的回调，然后卸载模块。进程退出才 Py_FinalizeEx。

门禁（按序，不可跳）

1 桩编译Debug 编过 :cpython 与 :python。不链 python312.lib。
2 登记表plugin_fn_test 查到 mark / click / gis 名。codegen_ir_test 仍绿。Op::kCount 仍为 105。
3 main()Debug 桩报 python not compiled in。Release 跑 browser.input、map2d.china、console、world3d.browse。未知名字在该调用抛出。
4 产品包Release plugin_python_test 用 import glang.plugin 启动 hello 与 analysis。PluginHost 签名不动。
5 删除仅在 3、4 都绿之后。ANTLR / Op / smartgis 删除。Debug 桩仍能编。
最终Release：核心语法三测全绿，并且浏览器场景 suite 与 11 个插件 suite 的 marks / score_id 都过。Debug 桩不能代替这一条。

命令与断言在计划 2026-10-18-glang-cpython-plugin.md。build.bat … harness 的 --gate 只跑 browser.gpu 与 browser.harness，不是最终场景门禁。
