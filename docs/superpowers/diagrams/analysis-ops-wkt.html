analysis ops：WKT 边界与 OGR 算法

字符串只在边界进出。算法层看到的是 OGRGeometry。

边界

content/browser/glang.runtime/ir/gis/（verb / measure / transform / feature）保持 opcode 的 WKT / 错误字符串签名。先检查 CRS，再调用 WKT 层，然后把 OGRGeometry 交给算法。

编解码

ops/wkt/ 做 WKT。ops/geojson/ 做 GeoJSON。两边都不跑空间运算。几何所有权类型在 ops/ir/ogr_geom.h。

一条几何 IR

ops/ir/：geometry_ir 每个 op 是一个节点，eval_geometry_ir 按 id 求值；GEOS 内核在 ops_geos。只见 OGRGeometry。

调度

ops/runner/ 组合边界编解码和 eval_geometry_ir。apply_op 只取出几何结果。栅格、地质、化探、拟合、路径按 id 转发，转发代码也在这个目录。

  1. CRS 检查（未知 CRS、CRS 不一致、地理坐标系）发生在解析 WKT 之前。
  2. WKT 层产出 OgrGeom。
  3. 算法返回新的 OGRGeometry，或就地改投影。
  4. 边界再导出 WKT、"1"/"0" 或数字字符串。
