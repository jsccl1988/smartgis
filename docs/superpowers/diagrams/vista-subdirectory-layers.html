Vista — IR 与 GPU

一颗 vista.dll。Component（component/map / component/world）在 CPU 上并行产出中间结果；Pass（pass/map / pass/world）在设备线程上做上传、计算和一条 CommandList 录制。「逻辑 / 物理」不再用作目录词。frame/ 与 scene/ 不在目标布局里。上一代 Scenic 把两边焊在同一个类型里。

Spec：§Vista IR/Pass lanes · 模块：src/vista/README.md
相关图： World 顶层 World LOD terrain 上一代 Scenic A×B 并行 content present GIS MapFrame

1. 核心分层

gis.dll — 数据

  • Style / Tile / Feature / MapLayer
  • 停在 POD 边界：LayerBatch
  • 硬墙：不依赖 vista.dll，不依赖 render/rhi

IR — CPU 可并行

  • component/map/ Layout → MapIR
  • component/world/ 根 World + Instance；顶层 space/ · instance/ · terrain/ · pointcloud/
  • component/world/terrain/ policy · grid · 按源 seed（raster / nested / surface / TIN）
  • mesh（fill/·line/·detail/）CPU 三角化；terrain DEM bake（头文件无 World）
  • assets 模型 / 3D Tiles / 点云文件
  • component/atmosphere 场；domain 缝
  • Emit 走 base::execution；工人只写自己的槽

Pass — 设备线程

  • pass/map/ MapPass 上传并编码
  • pass/world/ WorldPass：sync_from 再 record_draws
  • pass/world/terrain/ TerrainPass（由 WorldPass 组合）
  • pass/atmosphere/ pass + 海洋 FFT Compute
  • 顺序：Upload → Compute → Record，一条 CommandList
  • 这一侧不进入 parallel_for。无 vista::pass 命名空间

设备与上屏

  • src/render Vista DX12 / Vulkan
  • content stage_frame：UI 返回，不 join
  • graph::present 消费已录好的列表
  • Scenic scenic.dll 不编进本 DLL

2. 原理流（2D / 3D 共用阶段）

VISTA_LAYOUT_PARALLEL=0 把 2D Emit 收成 N=1（驱动 Layout emit）。GPUSCENE_PREP_PARALLEL 字面量保持，默认关，驱动 WorldPass prep。大气场由宿主投影进 GPU pass，GPU 目标不依赖 world。

3. 一帧阶段（播放）

就绪

Record 顺序：大气 pre-opaque（天空 / 深度）→ 不透明地表 → 大气 post-opaque（海洋、云、雾）→ 2D 叠加。Compute 在 Record 之前完成。

4. 目录（IR / Pass）

目录角色线程
vista/component/mapCPU IR：根 Layout → MapIR（伞头 ir.h）。职责目录 carto（含 collision）/ shade / place / mvt / layout（扁平）Emit 可并行；碰撞串行。map_sources 禁止依赖 render
vista/pass/mapGPU：根 MapPass / map_effect；detail/{atlas,encode,upload}。GN map_pass_sources设备线程。依赖 map_sources + render
vista/component/world根 World + Instance。顶层 space/（坐标、视域、视锥、octree）· instance/（sync、paint、lit 策略、tess）· pointcloud/ · terrain/（policy · grid · mesh · 按源 seed）。instance/paint.h 含 rgba_from_resolved_paint。space 与 instance 互不 includeCPU。world_sources 依赖 mesh，禁止依赖 render
vista/pass/worldGPU：根 WorldPass / GpuMesh / opaque_effect；detail/{upload,tint,rebuild,draw,record}；cull/frustum_camera。sync_from / record_draws 仍在 WorldPass设备线程。依赖 world_sources + render
vista/assets模型、3D Tiles、点云文件解码。不改名CPU。不依赖 world
vista/meshCPU xyz+indices。公开 tessellate.h；职责子目录 fill/·line/·detail/CPU。不依赖 world / render
vista/terrainDEM 栅格、hillshade、land mask。不改名CPU。头文件无 World
vista/domainDomainSession 缝。不改名CPU
vista/component/atmosphereCPU：根 Environment；field/ · ocean/ · cloud/；detail/math.hCPU。session_sources / atmosphere_cpu_sources 禁止依赖 render
vista/pass/atmosphereGPU：根 AtmosphereFrame / effects；ocean/cloud/sky/fog/globe；detail/{mesh,raster,field_texture}设备线程。依赖 atmosphere_cpu_sources + render。不依赖 session_sources

没有 map/gpu、world/gpu 或 atmosphere/gpu。没有公共命名空间 vista::map_pass / vista::atmosphere_pass。content 的 present/map2d 与 present/scene3d 目录不动。权威节：§Vista IR/Pass lanes。

6. 两代优缺点

Vista（当前代）Scenic（上一代）
加速落在哪 CPU：Emit×N 写 MapIR / Instance，工人不碰 Device。GPU：Vista 上 Upload、海洋 FFT、一条 CommandList 2D：Raster×N，每人一块私有 HDC，汇合后 BitBlt。3D：Prep×N 只做视锥，然后 GL Draw 或 D3D11 deferred
优点 2D 与 3D 共用阶段和设备。MapIR 同时喂软件出口和 GPU 出口，制图只做一次。gis 不依赖 vista，CPU 目标编译期进不了 RHI。UI 在 stage_frame 后返回 脏矩形按瓦片或图层光栅，合成只搬脏块。LP→DP 紧挨 HDC。GDI / GDI+ / Skia / GL / D3D 能挂在引擎里做同等对比。帧拍（代次、丢弃过期帧）已经跑过
缺点 冷帧先做完 CPU IR 再上传。热帧靠 DrawCache / 静帧复用。GPU 录制仍是一条 CommandList。prep 并行默认关。WorldPass 仍同时提供 sync_from 与 record_draws（CPU 翻译单元在 world/，不把同步拆成返回值） 逻辑和录制在 MapPainter、Scene::Render 里绑死。2D 与 3D 是两套设备。工人持有 HDC，和 HWND 绑在一起。D3D11 deferred 的线程局部上下文不能带到 Vista。上屏在引擎内部

分工：Vista 做默认 2D/3D 产品路径。Scenic 留在同等对比和 GDI 脏区光栅，用来核对画面。
