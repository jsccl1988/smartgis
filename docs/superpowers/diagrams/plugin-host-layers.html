plugin/runtime/host 按职责收紧

13 个同级薄目录收成 7 个。身份在 catalog/，DLL 管线在 native/，不透明门面在 capability/。命名空间仍是 plugin。导出宏留在 host 根上。

分层（谁拥有什么）

ui · Views 表

  • ui/manager_view 只画启用 / 信任 / 安装
  • 依赖 catalog 的 Registry / Store
  • catalog 不包含 Views

catalog · 包身份

  • manifest 解析 plugin.json
  • signature 验签，registry 启用与信任
  • store 装 zip / HTTP 索引
  • resource_roots 每包资源根

native · 加载管线

  • exports.h C ABI：init / run / destroy
  • scan 扫 --plugins-dir
  • NativeModule LoadLibrary
  • PluginManager 组合 scan + module + Registry

catalog 不包含 native。native/manager 单向依赖 catalog/registry。

旁边三条不并进 catalog 的车道

capability · 不透明门面

capability.h 与 scene3d_sink / map2d_sink / report_bridge / shell_ui / shell（HarnessShell）/ scenario / marks 同级。

chrome 只在调度期间挂上 app.views.harness。

processing · 计算池

ProcessingPool 在 worker 上算，present / done 回到排空线程。

注册 id：plugin.processing_pool。不是 catalog 记录。

present · GisDocument

gis_present：多边形、折线、样式、stand-in mesh。

不是已注册能力。产品 present 不包含 app/views。

原则流（扫描到销毁）

1 scannative/scan 读一层子目录
→
2 parsecatalog/manifest
→
3 trustsignature + Registry
→
4 loadNativeModule 解析 init
→
5 runPluginManager::dispatch_event
→
6 destroy卸载；HostCapabilities detach

安装 zip 走 Store，写回同一本 Registry，不另开一套记录类型。
